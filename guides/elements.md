# Elements

> The framework styles real HTML tags first. Every entry has a partial under [src/styles/elements/](../src/styles/elements/). Substantive entries (those declaring `--set-{tag}-*` tokens) are mirrored in [src/browser/elements.ts](../src/browser/elements.ts) and parity-tested.

This document is two things in one:

- A **status checklist** of every styled tag â€” what's done, what carries a small framework override, what's pure preflight-handled.
- A **reference catalog** describing each tag's semantics, default UA styles, and quirks. Useful both for contributors authoring a partial and for consumers reading our markup choices.

The checklist columns:

- **Tag** â€” the HTML element.
- **Status**:
  - `âœ… done` â€” substantive `_{tag}.scss` partial with token-driven cascade + TS entry + tests (only `<button>` so far).
  - `ðŸŸ¡ override` â€” partial keeps a small framework-essential rule that Tailwind preflight + UA defaults don't cover (e.g., underline on `<a>`, `cursor: help` on `<abbr>`, `min-inline-size: 0` on `<fieldset>`).
  - `ðŸš« n/a` â€” partial is comment-only documentation; no rules emitted. Tailwind v4 preflight + UA defaults handle everything semantic. The vast majority of elements fall here.
- **Description** â€” semantics, browser defaults, and styling quirks. Edit when you bring up an element so the entry reflects what we actually ship, not just what the spec says.

**Element-rule philosophy** â€” the framework relies on Tailwind v4's preflight as the reset layer, plus UA defaults where preflight doesn't touch. A framework rule only ships when it adds something neither layer provides:

- `<a>` keeps an underline (preflight strips it via `text-decoration: inherit`; the framework wants links visually distinct by default).
- `<abbr>` adds `cursor: help` (preflight covers the dotted underline; cursor is a separate signal).
- `<address>` resets to `font-style: normal` (UA italic is widely considered an unwanted quirk).
- `<fieldset>` zeroes `min-inline-size` (UA `min-content` blocks shrinking inside flex/grid).
- `<mark>` swaps UA hardcoded `yellow`/`black` for the system `mark`/`marktext` keywords + a dark-mode override using `highlight`/`highlighttext` (accessibility + forced-colors compat).
- `<p>` adds `p + p { margin-block-start: 1em }` to restore inter-paragraph rhythm (preflight's universal `* { margin: 0 }` strips paragraph spacing).
- `<button>` is the substantive baseline â€” full token-driven cascade (variant / size / style / state).

Every other element file is a comment-only placeholder. If a future element needs framework rules, this is the test: **does Tailwind preflight already do it?** If yes, no partial rules. If no, but it's just an opinionated style choice, no rules â€” let consumers add utilities. If no, AND it's a real semantic gap (UA quirk needing reset, or semantic affordance neither preflight nor browser provides) â€” then a framework rule earns its place.

## Deprecated elements

Removed from the spec; do not use. (`<acronym>`, `<applet>`, `<basefont>`, `<big>`, `<center>`, `<dir>`, `<font>`, `<frame>`, `<frameset>`, `<noframes>`, `<strike>`, `<tt>`.) No partial, no entry. Use modern equivalents.

## Non-visual elements

Valid and useful, but never rendered on screen and carry no CSS styling. They live in HTML but get no partial in `src/styles/elements/`. Documented here for completeness.

| Tag          | Role                                                                                                                                                                                       | Why no CSS                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| `<area>`     | Clickable hotspot (`rect`/`circle`/`poly`/`default`) inside a `<map>`, activated by `<img usemap="#name">`.                                                                                | Void element with no rendered box â€” regions are invisible by nature.           |
| `<base>`     | Sets the base URL for all relative URLs in the document and/or the default link `target`. One per page; lives in `<head>`.                                                                 | Metadata only; never rendered.                                                   |
| `<br>`       | Semantic line break. Use only where a newline is meaningful (poetry, postal addresses) â€” not as a paragraph spacer.                                                                      | Void element with no box model â€” `margin` and `padding` have no visual effect. |
| `<head>`     | Document metadata container. Houses `<title>`, `<meta>`, `<link>`, `<style>`, `<script>`, `<base>`. Must be first child of `<html>`.                                                       | Never rendered (`display: none`).                                                |
| `<link>`     | External resource relationship (`rel="stylesheet"`, `rel="icon"`, `rel="preload"`, etc.). `rel` is required. Lives in `<head>`.                                                            | Metadata only; never rendered.                                                   |
| `<map>`      | Named container for `<area>` hotspots. `name` must match the `usemap="#name"` value on the target `<img>`.                                                                                 | Generates no visible box despite `display: inline`.                              |
| `<meta>`     | Metadata descriptor â€” charset, viewport, SEO description, Open Graph, HTTP-equiv headers. Lives in `<head>`.                                                                             | Never rendered.                                                                  |
| `<noscript>` | Fallback content shown when JS is disabled. In `<head>`: may contain `<link>`/`<style>`/`<meta>`; in `<body>`: any flow content.                                                           | Special-case fallback; not part of the normal visual content flow.               |
| `<param>`    | Passes a named `name`/`value` parameter to a parent `<object>` element. Must be a first child of `<object>`.                                                                               | Never rendered (`display: none`).                                                |
| `<script>`   | Loads or embeds JS. Without `async`/`defer` blocks HTML parsing. `type="module"` defers by default. Inline content must not contain `</script>` literally.                                 | Never rendered (`display: none`).                                                |
| `<source>`   | Provides alternative media URLs for `<picture>`, `<video>`, or `<audio>`. In `<picture>`, must appear before the required `<img>`.                                                         | Void element; data only â€” no rendered box.                                     |
| `<style>`    | Embeds a CSS stylesheet. Prefer `<link rel="stylesheet">` for performance; `<style>` in `<body>` can cause FOUC.                                                                           | Never rendered (`display: none`).                                                |
| `<template>` | Inert HTML fragment â€” parsed but not rendered until cloned via JS (`element.content`). Scripts and images inside are inert. Used in Web Components.                                      | Never rendered (`display: none`).                                                |
| `<title>`    | Document title shown in the browser tab, bookmarks, and used as the primary search-result headline. Required in `<head>`.                                                                  | Never rendered in the page body.                                                 |
| `<track>`    | Timed text track (subtitles, captions, chapters, descriptions, metadata) for `<video>` or `<audio>`. Points to a `.vtt` file. `kind` and `default` attributes control type and activation. | Void element; data only â€” no rendered box.                                     |
| `<wbr>`      | Word break opportunity â€” hints where the browser may break a long word (e.g., a URL) without adding a hyphen. No break occurs if the line fits.                                          | No box model; purely a rendering/line-break hint.                                |
