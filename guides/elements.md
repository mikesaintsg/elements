# Elements

> Authoritative reference for every native HTML element the framework has an opinion on, plus the token-uniformity groups that bind families of elements to a shared minimum surface. Every entry has a partial under [src/styles/elements/](../src/styles/elements/); substantive baselines that live in `elements/_*.scss` are mirrored in [src/browser/elements.ts](../src/browser/elements.ts), and the full registry — treatment, composable pairing, group membership — lives in [src/browser/taxonomy.ts](../src/browser/taxonomy.ts).

## Surface

[`taxonomy.ts`](../src/browser/taxonomy.ts) assigns every element exactly one of **four** treatments. This guide collapses them into **three** status symbols (`substantive` and `composable` both render the token-driven modifier cascade, so both read as `✅ cascade`):

- **`✅ cascade`** — taxonomy treatment `substantive` **or** `composable`. The `_{tag}.scss` partial declares element-scoped `--set-{tag}-*` tokens and renders the full token-driven modifier cascade; substantive baselines living in `elements/_*.scss` are mirrored in [`src/browser/elements.ts`](../src/browser/elements.ts), and `composable` entries additionally pair a Vue composable + framework-agnostic factory under [`src/browser/`](../src/browser/) (`useAside`, `useNav`, `useMenu`, `useTable`, `useButton`, `useForm`, `useToast`, `useSelect`, `useDetails`, `useDialog`). Covered by behaviour tests under [`tests/src/styles/elements/`](../tests/src/styles/elements/).
- **`🟡 override`** — taxonomy treatment `reset`. The partial normalizes a UA default (or rebuilds a preflight-stripped baseline) with a small, framework-essential rule that neither Tailwind v4 preflight nor the UA supplies. No element-scoped `--set-{tag}-*` tokens, no `elements.ts` mirror entry, no modifier cascade.
- **`🚫 n/a`** — taxonomy treatment `passthrough`. The partial is a comment-only placeholder. Tailwind preflight + UA defaults handle everything. The largest bucket.

The composition layer ([components.md](components.md)) wraps these element baselines into class-root widgets (`.toast`, `.tooltip`, `.field`, `.card`, …). Element layer styles the tag; component layer styles the named pattern.

Taxonomy `reset` (14). The partial normalizes a UA default (or rebuilds a preflight-stripped baseline) with a small framework-essential rule — no element-scoped tokens, no cascade, no `elements.ts` entry.

| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<html>`          | Reset-only partial. Preflight zeroes the UA margin; carry `lang` for screen readers + search engines.                                                                                                                                                                                                                                                                                                        |

### Non-styled elements (n/a)

Taxonomy `passthrough` (26). Ship as comment-only placeholders — Tailwind v4 preflight + UA defaults handle everything.

- **Generic container** — `<div>`. (The framework intentionally ships no element-layer rules.)
- **Inline phrasing** — `<bdi>`, `<bdo>`, `<cite>`, `<dfn>`, `<em>`, `<q>`, `<s>`, `<span>`.
- **Demarcating edits** — `<del>`, `<ins>`. (UA `line-through` / `underline`.)
- **Ruby annotation** — `<ruby>`, `<rt>`, `<rp>`. (East Asian typography.)
- **Table internals** — `<caption>`, `<col>`, `<colgroup>`, `<thead>`, `<tbody>`, `<tfoot>`, `<tr>`, `<th>`, `<td>`. The tags themselves are passthrough; their typography is governed by the `<table>`-family token namespace via the `<table>` cascade.
- **Legacy form bits** — `<datalist>`, `<optgroup>`, `<option>`. (Custom select chrome ships through `<select>`'s cascade + the `useSelect` composable, not by styling the options.)

> Sectioning landmarks `<article>`, `<header>`, `<footer>`, `<main>`, `<section>`, `<hgroup>` are all **substantive** (cascade) — they ship hydrated padding gutters + flex-column rhythm so a bare container reads cleanly. `<html>` / `<body>` are `reset` (override). `<math>` / `<svg>` / `<canvas>` are substantive. `<ul>` / `<ol>` / `<li>` and `<b>` / `<i>` / `<sub>` / `<sup>` / `<picture>` are `reset` (override). `<data>` / `<time>` / `<small>` / `<strong>` / `<u>` are substantive (cascade).

### Deprecated

Removed from the spec; do not use. No partial, no entry: `<acronym>`, `<applet>`, `<basefont>`, `<big>`, `<center>`, `<dir>`, `<font>`, `<frame>`, `<frameset>`, `<noframes>`, `<strike>`, `<tt>`. Use modern equivalents.

## Contract

These invariants hold across `_{tag}.scss` partials ↔ `elements.ts` ↔ `taxonomy.ts` ↔ this guide. They mirror the eight parity layers in [`tests/guides/elements.test.ts`](../tests/guides/elements.test.ts):

1. **Shape.** `elements.ts` is a frozen key=value mirror — every key equals its value and the `Element` type narrows to the union of values.
2. **TS → SCSS.** Every key in `elements.ts` has an `_{tag}.scss` partial that declares at least one `--set-{tag}-*` token.
3. **SCSS → TS.** Every `_{tag}.scss` that declares a `--set-{tag}-*` token appears as a key in `elements.ts` (the `h1-h6` multi-tag partial is the documented exception — it uses the shared `--set-heading-*` namespace, not per-tag tokens).
4. **Taxonomy shape.** Every `taxonomy.ts` entry carries tag / category / treatment; `composable` is non-null iff `treatment === 'composable'`; every tag appears exactly once; the pre-computed indices (`TAXONOMY_BY_TAG`, `SUBSTANTIVE_TAGS`, `COMPOSABLE_TAGS`, `RESET_TAGS`, `PASSTHROUGH_TAGS`, `MODIFIABLE_TAGS`) stay in sync.
5. **Partial parity.** Every `taxonomy.ts` entry has a matching `_{tag}.scss` partial (even passthroughs ship a comment-only stub) and vice versa.
6. **Token coverage.** Every `substantive` or `composable` entry declares at least one `--set-{tag}-*` token somewhere in `elements/` or `components/`.
7. **Factory pairing.** Every `composable` treatment entry references a real `src/browser/factories/create{Name}.ts`.
8. **Token uniformity per group.** Every member of every `TOKEN_GROUPS` group declares every required suffix with the `--set-{member}-` prefix — see [Token-uniformity groups](#token-uniformity-groups) below.

Enforced by [`tests/guides/elements.test.ts`](../tests/guides/elements.test.ts) (the single driver covers all eight contracts), plus a markdown-table doc-parity sweep: every `elements.ts` key and every `substantive` / `composable` taxonomy entry must have a `<tag>` mention in this guide. Per-element behavioural tests under [`tests/src/styles/elements/`](../tests/src/styles/elements/) cover UA-reset + modifier-cascade correctness on real Chromium.

## Patterns

### Element-rule philosophy

A framework rule only ships when neither Tailwind preflight nor the UA default supplies what we need. Three criteria, each with examples:

- **UA quirk that breaks layout / accessibility / forced-colors.** `<fieldset>` zeroes `min-inline-size` (UA `min-content` blocks shrinking inside flex/grid). `<mark>` swaps UA hardcoded `yellow`/`black` for the system `mark` / `marktext` keywords plus a `prefers-color-scheme: dark` override using `highlight` / `highlighttext`. `<address>` resets `font-style: normal` because the UA italic is a widely-rejected quirk.
- **Affordance preflight strips.** `<a>` keeps an underline (preflight drops it via `text-decoration: inherit`; the framework wants links visually distinct). `<abbr>` adds `cursor: help` (preflight covers the dotted underline; cursor is a separate signal). `<p>` adds `p + p { margin-block-start: 1em }` to restore inter-paragraph rhythm after preflight's universal `* { margin: 0 }` strip.
- **Earns the full modifier cascade.** Interactive controls (`<button>`, `<a>`, `<input>`, `<select>`, `<textarea>`, `<label>`, `<fieldset>`, `<legend>`), disclosure / dialog roots (`<details>`, `<summary>`, `<dialog>`, `<aside>`), gauges (`<meter>`, `<progress>`, `<output>`), and structural primitives (`<form>`, `<menu>`, `<nav>`, `<search>`, the `<table>` family) all carry element-scoped tokens and the modifier cascade described in [modifiers.md](modifiers.md).

If a future element needs framework rules, the test is: **does preflight already do it?** If yes, no partial rules. If no, but it's just an opinionated style choice, no rules — let consumers add utilities. If no, AND it's a real semantic gap (UA quirk needing reset, affordance preflight strips, or an element worth the full cascade) — then the rule earns its place.

### Open-state gating discipline

For any element with an open/closed lifecycle — `<dialog>`, `<details>`, `<aside popover>`, `<output popover>`, `<menu popover>` — the element baseline ships only tokens and chrome that survives the close transition. Drawer-shaped CSS (`display: flex`, `position: fixed`, large `transform`) lives in `composables/_{tag}.scss` and gates on the open-state selector: `:popover-open`, `:modal`, `[open]`, or `[data-{name}-open]`. Without the gate, author rules with specificity ≥ 0,1,1 defeat the UA's `display: none` for closed popovers and the element stays rendered after `.close()` / `.hidePopover()`. Full discipline in [composables.md §3](composables.md#3-openclosed-lifecycle).

| `boxed-container`    | `fieldset`, `details`                                                                             | `color`, `background-color`, `border-color`, `border-width`, `border-radius`, `padding-inline`, `padding-block`, `transition-duration`                        |
| `class-chip`         | `badge`, `tag` (class-components)                                                                 | `color`, `background-color`, `border-radius`, `padding-inline`, `padding-block`, `font-size`                                                                  |

An element can belong to multiple groups — `<details>` is `interactive` + `disclosure` + `boxed-container`. Required-suffix sets are unioned: each member declares the superset of every group's required tokens.

When a new element / class-component is added, audit it against this table — if it shares the visual shape of an existing group, add it as a member; if it introduces a new shared shape across multiple elements, register a new group with both as members. The parity test surfaces any member that doesn't declare every required suffix.

### Bringing up an element

Promoting an element from `🚫 n/a` or `🟡 override` to `✅ cascade`:

1. Refactor `_{tag}.scss` to use the modifier cascade per [styles.md author's contract](styles.md). Element-scoped tokens follow the [tokens.md](tokens.md) §"Element-scoped tokens" pattern; the fallback chain is `style → variant → size → shape → element default` (or whatever subset applies).
2. Add the tag to [`src/browser/elements.ts`](../src/browser/elements.ts) (unless its tokens live in `components/_{tag}.scss` rather than `elements/_{tag}.scss`).
3. Add the tag to [`src/browser/taxonomy.ts`](../src/browser/taxonomy.ts) with treatment `substantive` (or `composable` if a factory ships alongside).
4. If the element has an open / closed lifecycle, move drawer-shaped CSS into `composables/_{tag}.scss` gated on the open-state selector — see [Open-state gating discipline](#open-state-gating-discipline) and [composables.md §3](composables.md#3-openclosed-lifecycle).
5. Write a behaviour test under `tests/src/styles/elements/_{tag}.test.ts` covering UA reset, modifier cascade, and any element-specific quirks.
6. Update this guide — change the status emoji, refresh the row in the Substantive elements table + Reference catalog.

Most `🚫 n/a` entries stay that way indefinitely. Promote to `🟡 override` only when a specific UA quirk demands a framework-essential rule, and to `✅ cascade` only when the element earns the full token-driven cascade.
